Lessons recorded so they are not repeated:
- Branch every PR from `origin/main`, never from another PR's branch; squash merges make the
  second PR conflict (#194).
- The static release gate proves the *exact* predecessor. When a title in
  `scripts/monitor-production.mjs` changes, set that route's `baselineMarker` to the title
  production currently serves, not an older one (#190).
- `app.js` + `styles.css` sit a few hundred bytes under their brotli budget. New frontend code
  belongs in a lazily imported module, as `achievements.js` and `shuffle-challenge.js` are.
- The CI accessibility audit is a real gate: do not dim text with `opacity`; keep 4.5:1.

## How to resume from another device

```
git fetch origin
git checkout -b <task-branch> origin/main
npm ci --no-audit --no-fund
```

Then pick checks by what changed (`CLAUDE.md`, Development and checks). Open a pull request
into `main`; merging it releases. Do not commit to `main` directly.
